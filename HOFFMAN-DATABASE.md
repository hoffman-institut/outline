# Блок «База данных» — устройство и ход работ

Базы данных внутри документов, как в Yonote/Notion, без отдельного сервиса. Блок вставляется через `/база` (`/database`).

## Модель данных

Данные живут в самом документе (ProseMirror → Y.js → PostgreSQL), поэтому права, история, совместная работа, поиск и API работают как для обычного текста.

- Узел `database` (блок, atom, `content: "database_row*"`). Атрибуты:
  - `id` — идентификатор блока.
  - `title` — название базы.
  - `templates: RowTemplate[]` — шаблоны записей `{ id, name, cells, pageId? }` (страница шаблона копируется через `documents.duplicate`).
  - `columns: Column[]` — столбцы. `Column = { id, name, type, options?, width?, formula?, relation?, rollup? }`, где тип — `text | number | select | multi_select | date | person | checkbox | url | email | phone | formula | relation | backlink | rollup`.
    - `options = [{ id, name, color }]` — для `select` и `multi_select`.
    - `width` — ширина в таблице, px (меняется мышкой за правый край заголовка).
    - `formula` — текст формулы, например `[Цена] * [Количество]`.
    - `relation = { documentId, databaseId }` — связанная база (id документа и id блока). У `backlink` ещё `columnId` — столбец-связь той базы, который ведёт сюда.
    - `rollup = { columnId, targetColumnId, fn }` — сводка: через какую связь, по какому столбцу связанной базы, что считать (`fn` — итог, как у `totals`, или `values`).
    - `numberFormat` (`grouped | ruble | dollar | euro | percent`), `showAs: "bar"` + `max` — вид чисел; `prefix` — у автономера (`auto_number`, номер ставится при создании строки); `withTime` — у даты: значения с временем хранятся как момент UTC (`2026-11-04T07:30:00.000Z`) и показываются в поясе зрителя, даты без времени — один и тот же день везде; `subitems` — у связи на эту же базу: родитель подзадачи.
    - `files` — ячейка хранит список JSON-строк `{id, name, url, type, size}` (вложения документа).
  - `views: View[]` — виды. `View = { id, name, type, sort, filters, filterMode?, hidden, groupBy?, groupDate?, dateColumn?, recurring?, calendarMode?, coverColumn?, newRowsFirst?, totals?, endColumn?, laneColumn?, colorColumn?, labelColumn?, weekdayColumn?, timelineScale? }`, где тип — `table | board | calendar | timeline | gallery | form`. Поля таймлайна — в разделе «Вид „Таймлайн“». `filters` — правила и группы `{ id, mode: and|or, rules }`, `filterMode` — как они объединяются. `groupBy` у таблицы — группировка строк (у дат `groupDate`: day|week|month|year). `totals = { [columnId]: count | not_empty | empty | percent_not_empty | unique | sum | avg | min | max | earliest | latest | checked | unchecked | percent_checked }` — итоги под столбцами таблицы.
- Узел `database_row` (atom, лист). Атрибуты `{ id, cells: { [columnId]: value }, docId? }`.
  - Каждая строка — отдельный узел, поэтому одновременная правка разных строк не конфликтует. В пределах одной строки побеждает последняя правка.
  - Значения ячеек:
    - текст, ссылка, почта, телефон — строка;
    - число — number;
    - выбор — id варианта; несколько вариантов — массив id;
    - дата — `YYYY-MM-DD`;
    - человек — массив id пользователей;
    - флажок — boolean;
    - связь — массив id строк связанной базы;
    - формула, обратная связь, сводка — ничего не хранят, считаются при показе.
  - `docId` — страница строки (дочерний документ), этап 3.
- Порядок строк в документе — ручной порядок. Сортировка вида только меняет порядок показа, документ не меняет.
- Сортировка `upcoming` для дат — по ближайшей годовщине без учёта года (дни рождения).

## Вычисляемые столбцы

`computeDatabase` (`shared/editor/lib/databaseCompute.ts`) считает формулы, связи, обратные связи и сводки при каждом показе. Вычисленные значения нигде не сохраняются. Столбец формулы или сводки получает тип своих значений (число, дата, флажок, текст), поэтому сортировка, фильтры и итоги работают с результатами. В коде интерфейса `data` — хранимые данные (только они идут в изменения), `computed` — для показа.

- **Формулы** (`shared/editor/lib/formula.ts`) — синтаксис русского Excel: `[Столбец]`, функции по-русски, `;` между аргументами. Выражение разбирается в дерево и вычисляется без `eval`. Пустая ячейка в арифметике и сравнениях `< > <= >=` даёт пусто (дата остаётся датой, пустая дата не «скоро»), `СУММ` считает пустые нулём. Переименование столбца правит формулы. Перевод формулы в обычный столбец сохраняет текущие результаты.
- **Связи** хранятся с одной стороны. Обратная связь — только чтение, ищет строки той базы, чья связь ведёт сюда. Одна база никогда не пишет в чужой документ.
- **Связанные базы** (`app/editor/components/Database/linked.ts`): из этого же документа читаются из редактора (проверка изменений раз в 1,5 с), из других — через `documents.info` и разбор markdown, кэш 30 с, обновление при возврате во вкладку. Нет доступа к документу — связь пустая, без ошибки.
- Связанная база считается на один уровень: её собственные связи и сводки не разворачиваются, поэтому базы, ссылающиеся друг на друга, не зацикливаются.

## Вид «Таймлайн»

График по дням: слева дорожки (например, сотрудники), справа полосы от даты начала до даты конца. Сделан для базы «Отсутствия» — кто когда в отпуске и где отпуска пересекаются. Логика — `shared/editor/lib/timeline.ts` (+ тесты), интерфейс — `app/editor/components/Database/TimelineView.tsx`, настройки — «Поля» (`ViewToolbar.tsx`).

Поля вида (все необязательные, значения — id столбцов; неизвестные значения нормализация отбрасывает):

| Поле | Что задаёт | Тип столбца |
|---|---|---|
| `dateColumn` | начало полосы (без него вид просит выбрать столбец) | `date` |
| `endColumn` | конец полосы, включительно; пустой «конец» у строки — полоса до сегодня (если начало в будущем — один день); нет поля — все полосы в один день | `date` |
| `laneColumn` | дорожки: одинаковые значения — одна дорожка; нет поля — первый столбец | любой |
| `colorColumn` | цвет полосы = цвет варианта; нет поля — синие полосы | `select` |
| `labelColumn` | текст на полосе и строка в подсказке; нет поля — значение `colorColumn` (и название, если дорожки не по первому столбцу) | любой |
| `weekdayColumn` | день недели: строка со значением — отметка в этот день каждую неделю | `select` с вариантами `Пн`…`Вс` (или `понедельник`, `Mon`) |
| `timelineScale` | `month` (по умолчанию) · `quarter` · `year` | — |

Правила показа:

- Обычная строка — полоса от начала до конца. Перепутанные даты меняются местами, строка без начала не показывается. Строка без конца (например, больничный без даты выхода) тянется до сегодня, в подсказке — «бессрочно»; если она начинается позже сегодня — полоса в один день.
- Строка с заполненным `weekdayColumn` — еженедельные отметки от начала до конца; пустое начало или конец не ограничивают (бессрочный выходной день недели).
- Дорожка есть у каждого значения `laneColumn` среди строк вида, даже без полос в показанном периоде. Строки без значения — дорожка «Без названия». Несколько значений (люди, теги) — строка на каждой своей дорожке. Полосы одной дорожки, которые накладываются, идут друг под другом.
- **Пересечения** — рабочие дни, где обычные полосы есть у двух и более разных дорожек; еженедельные отметки не считаются. Нерабочие дни производственного календаря (код `1`: выходные и праздники) не считаются, сокращённые (`2`) считаются; без календаря не считаются сб и вс. Такие дни подсвечены по всей высоте и отмечены в строке «Пересечения» (подсказка — даты и кто).
- Фильтры и поиск вида действуют как обычно: например, фильтр «Статус = Согласован» оставляет только согласованные.
- Выходные и нерабочие праздничные дни затенены по производственному календарю РФ, в масштабе «Месяц» сокращённые и праздничные дни подписаны в подсказке шапки. Сегодня — линия и выделенный день.
- Клик по полосе или отметке открывает карточку строки; подсказка — название, даты, значения видимых столбцов-выборов (тип, статус) и столбца подписи.
- Назад / Сегодня / Вперёд листают период, масштаб — кнопками или в «Полях». Читатели меняют вид у себя, без сохранения, как в других видах. В узкой колонке документа таймлайн прокручивается вбок внутри блока, дорожки остаются слева.

Пример вида для базы «Отсутствия»: цвет — по статусу (полоса берёт цвет варианта: например, «План» — серый, «Согласован» — зелёный), подпись — тип. Столбцы: `Сотрудник` — `who`, `Тип` — `type`, `Статус` — `status`, `С` — `from`, `По` — `to`, `День недели` — `wday`.

```json
{
  "id": "v-timeline",
  "name": "График",
  "type": "timeline",
  "sort": [],
  "filters": [],
  "hidden": [],
  "dateColumn": "from",
  "endColumn": "to",
  "laneColumn": "who",
  "colorColumn": "status",
  "labelColumn": "type",
  "weekdayColumn": "wday",
  "timelineScale": "quarter"
}
```

Новый вид из меню «+» сам берёт первые два столбца-даты как начало и конец, первый выбор как цвет и выбор с днями недели как `weekdayColumn`.

### Производственный календарь

`POST /api/calendar.holidays { year }` (только для вошедших пользователей, 100 запросов в минуту) → `{ data: { year, days, source } }`. `days` — строка из цифр по дням года: `0` рабочий, `1` нерабочий, `2` сокращённый. Источник — `https://isdayoff.ru/api/getdata?year=YYYY&cc=ru&pre=1` (таймаут 5 с), ответ кэшируется в Redis на 3 дня (`production-calendar:ru:<год>`). Если сервис недоступен или года у него нет (отвечает `101`), `source: "weekends"` — выходные только сб/вс, повторная попытка через 10 минут. Код — `server/utils/productionCalendar.ts`, `server/routes/api/calendar`. Клиент запрашивает годы показанного периода и держит их до перезагрузки страницы; без ответа (публичная ссылка, ошибка) считает выходными сб/вс.

## Связанная база

Узел `database_view` (atom): `{ id, source: { documentId, databaseId } | null, views }`. Показывает базу-источник со своими видами. Источник в этом документе — правки идут в узел-источник через редактор; в другом документе — строки через API (`databases.addRow/updateRow/deleteRow`), столбцы только для чтения, данные перечитываются каждые 20 с и при возврате во вкладку. Markdown — блок ```` ```hoffman-database-view ```` с JSON. Вставка — `/связанная база`.

## API строк

`server/routes/api/databases`: `databases.addRow { documentId, databaseId, cells?, rowId? }`, `databases.updateRow`, `databases.deleteRow`. Правка применяется к Y.js-состоянию документа как правка редактора (`updateYFragment`), хук модели уведомляет сервер совместного редактирования — открытые редакторы вливают изменение. Значения проверяются по типам столбцов (варианты выбора можно передать названием). Читатель документа может только `addRow`, только если у базы есть вид «Форма» и документ не в архиве — с полями формы, без файлов. Текст ячейки — до 10 000 символов, `rowId` не может повторять существующую строку. Страховка: через 15 с проверяется, что сохранённое Y.js-состояние содержит нашу правку (вектор состояния: клиент и clock правки); если открытый редактор сохранил старое состояние поверх — строка добавляется снова, а строка, удалённая человеком после слияния, не возвращается. Дубли по id показываются один раз.

## Markdown

API, MCP и импорт работают через markdown (`applyMarkdownToDocument`), поиск индексирует `documents.text`. Поэтому база сериализуется без потерь в блок:

````
```hoffman-database
{ "title": …, "columns": […], "views": […], "rows": […] }
```
````

Правило markdown-it превращает такой блок в токены `database_open` / `database_row` / `database_close`.

## Файлы

- `shared/editor/lib/database.ts` — типы, значения по умолчанию, форматирование, сортировка, фильтры, итоги (общий код для клиента и сервера) + тесты.
- `shared/editor/lib/formula.ts`, `databaseCompute.ts` — формулы и вычисляемые столбцы + тесты.
- `shared/editor/nodes/Database.ts`, `DatabaseRow.ts` — схема, markdown, команды. Подключены в `richExtensions`.
- `shared/editor/rules/database.ts` — правило markdown-it.
- `app/editor/nodes/DatabaseView.tsx` — клиентский подкласс с React-компонентом. Подменяется в `withUIExtensions`.
- `shared/editor/lib/timeline.ts` — таймлайн: периоды, полосы, еженедельные отметки, пересечения, разбор производственного календаря + тесты.
- `app/editor/components/Database/*` — интерфейс: таблица, канбан, календарь, таймлайн, меню столбцов, редакторы ячеек.
- `server/utils/productionCalendar.ts`, `server/routes/api/calendar` — производственный календарь для таймлайна.
- `app/editor/components/ComponentView.tsx` — события внутри `[data-database-ui]` не уходят в ProseMirror.
